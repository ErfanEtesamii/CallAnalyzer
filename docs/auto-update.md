# به‌روزرسانی خودکار (بدون نصب مجدد)

هدف: هر تغییری که می‌دهید فقط **یک بار** (commit/push) انجام شود و هم سرور هم افزونه‌ی همه‌ی کروم‌ها خودشان به‌روز شوند.

```
شما: git push
        │
        ├─► سرور ویندوز (Task: CallAnalyzerAutoUpdate، هر ۲ دقیقه، deploy\auto_update.ps1)
        │       git pull ← پیش‌بررسی ← ری‌استارت سرویس ← بررسی /health ← (در خطا) برگشت به commit قبلی
        │
        └─► هر کامپیوتر کاربر (Task: CallAnalyzerExtSync، هر ۳ دقیقه، client\sync.ps1، بدون ادمین)
                فایل‌های تغییرکرده را از بک‌اند می‌گیرد ← manifest.json را آخر عوض می‌کند
                    └─► افزونه نسخه‌ی manifest روی دیسک را می‌بیند و خودش reload می‌شود (lib/updater.js)
```

## چه تغییری چه چیزی را لازم دارد

| تغییر در | ری‌استارت سرور | به کاربر می‌رسد |
|---|---|---|
| `extension/**` (UI، content script، صف…) | **نه** (بک‌اند همان لحظه از دیسک سرو می‌کند) | خودکار، ≈ ۳–۵ دقیقه |
| `rubric/**` | نه (hot reload با `/api/v1/rubric/reload`) | — (سمت سرور است) |
| `backend/app/**`، `config/**`، `backend/.env` | بله، خودکار | — |
| `backend/requirements.txt` | pip install + ری‌استارت، خودکار | — |

## نصب (یک‌بار)

### ۱) سرور ویندوز — با ادمین
پیش‌نیاز: سرویس با `deploy\install_service.bat` نصب شده و پوشه‌ی پروژه یک clone از ریپوی شماست (`git clone`).
```
deploy\install_autoupdate.bat main        ← نام branch (پیش‌فرض main)
```
- لاگ: `logs\autoupdate.log`. تست دستی: `powershell -ExecutionPolicy Bypass -File deploy\auto_update.ps1`
- اجرا با کاربر SYSTEM است؛ برای ریپوی خصوصی، remote باید بدون سؤال کار کند (مثلاً deploy token فقط‌خواندنی داخل URL).
- بدون git هم کار می‌کند: فایل‌ها را مستقیم روی سرور ویرایش کنید؛ اسکریپت تغییر را با هش می‌فهمد و ری‌استارت می‌کند (بدون امکان rollback).
- اجرای اول فقط «خط پایه» را ثبت می‌کند (فرض: سرویس در حال اجرا با همین فایل‌هاست).
- اگر روی سرور فایل ردیابی‌شده را دستی تغییر داده باشید، pull انجام نمی‌شود (چیزی بازنویسی نمی‌شود) و در لاگ نوشته می‌شود.
- commit خراب (خطای سینتکس، یا سرویس بعد از ری‌استارت `/health` نداد) → خودکار برگشت به commit قبلی و تا commit جدیدتر دوباره امتحان نمی‌شود. `-RunTests` تست‌های pytest را هم به پیش‌بررسی اضافه می‌کند.

### ۲) برای هر کاربر — بدون ادمین
روی سرور یک‌بار بسته را بسازید و بدهید:
```
python3 scripts/make_client.py --url http://192.168.10.5:8000 --token <API_TOKEN>
```
کاربر `dist\CallAnalyzer-Client.zip` را باز می‌کند و `install-client.bat` را دوبار کلیک می‌کند. این کار:
1. اکستنشن را از سرور در `%LOCALAPPDATA%\CallAnalyzer\ext` می‌گذارد،
2. همگام‌ساز را در Task Scheduler **همان کاربر** ثبت می‌کند (اگر مجاز نبود: در Run کاربر)،
3. مسیر را کپی می‌کند. کاربر فقط یک‌بار در `chrome://extensions` ← Developer mode ← Load unpacked ← همان مسیر.

بسته فقط نصب‌کننده و آدرس/توکن است؛ با تغییر کد اکستنشن **دیگر نیازی به ساخت دوباره‌ی آن نیست**. حذف: `install.ps1 -Uninstall`.

## چرا این طراحی (محدودیت‌های Chrome)
- افزونه‌ی MV3 نمی‌تواند کد را از اینترنت/سرور اجرا کند (CSP و بدون `eval`)، پس «کد از سرور» ممکن نیست؛ باید فایل‌های افزونه روی دیسک عوض شوند.
- به‌روزرسانی خودکار Chrome برای افزونه‌ی خارج از Web Store فقط با policy (ادمین/دامنه) کار می‌کند؛ کاربران عادی فقط «Load unpacked» دارند و آن هم خودکار به‌روز نمی‌شود.
- راه‌حل: فایل‌های پوشه‌ی unpacked را یک وظیفه‌ی کاربری (بدون ادمین) همگام می‌کند و خود افزونه با `chrome.runtime.reload()` نسخه‌ی جدید را برمی‌دارد.

## جزئیات رفتار
- **امنیت:** فهرست و فایل‌ها فقط با توکن (`Authorization: Bearer`) سرو می‌شوند. `src/preset.json` (آدرس+توکن) هرگز سرو یا بازنویسی نمی‌شود. همگام‌ساز فقط `manifest.json`، `src/**` و `assets/**` می‌پذیرد، مسیر با `..` را رد می‌کند و هش هر فایل را قبل از جایگزینی می‌سنجد؛ اگر یکی ناجور بود هیچ فایلی عوض نمی‌شود.
- **نسخه:** بک‌اند از هش محتوای فایل‌ها نسخه‌ی `a.b.x.y` می‌سازد (دو بخش اول از `extension/manifest.json`). نیازی نیست دستی نسخه بالا ببرید؛ فقط وقتی تغییر بزرگ است `version` را در manifest عوض کنید.
- **reload ایمن:** افزونه وسط دانلود/آپلود reload نمی‌شود (حداکثر ۳۰ دقیقه صبر؛ کارهای نیمه‌کاره بعداً بازیابی می‌شوند) و حداقل ۲ دقیقه بین دو reload فاصله می‌گذارد.
- **تب‌های باز پنل:** بعد از reload، content script جدید خودکار در تب‌های باز پنل تزریق می‌شود (نیازی به F5 نیست). پنل کناری ممکن است بسته شود؛ دوباره روی آیکون بزنید.
- **عیب‌یابی کلاینت:** لاگ در `%LOCALAPPDATA%\CallAnalyzer\sync.log`. اگر سرور نسخه‌ی جدیدتری دارد ولی ۲۰ دقیقه روی کامپیوتر نیامده، در تنظیمات افزونه هشدار نشان داده می‌شود.
- **تغییر host_permissions در manifest:** برای unpacked بعد از reload بدون پرسش اعمال می‌شود. آدرس بک‌اند باید در `host_permissions` باشد (`make_client.py` هشدار می‌دهد).
- **توکن در ریپو:** `extension/src/preset.json` در `.gitignore` است. اگر قبلاً commit شده: `git rm --cached extension/src/preset.json` و توکن را عوض کنید. نمونه: `preset.example.json`.
